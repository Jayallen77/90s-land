**For the current GitHub-main workflow and exact Hermes instructions, start with
[DEPLOYMENT.md](../DEPLOYMENT.md).** It supersedes the generic VPS placeholders
below. The existing Caddy document root is
`/home/justin/sites/90s-land-releases/current`; the active release contents and

The Git checkout is an authoring/build workspace, **never the public web root**.
Generated HTML is committed alongside sources for review and source-only previews.
A Git pull alone does not create a production release. `dist/` is intentionally
ignored and must be rebuilt after pulling the reviewed revision.

## Directory contract

Run `python3 -B tools/build_release.py` (or `pnpm build`) from a clean checkout.
The canonical build output is **`dist/release/public/`**. The builder needs
Python **3.10 or newer**, with only its standard library, on Linux or macOS.
Node, pnpm, Pillow, and fonttools are for authoring/testing, not VPS packaging.
Committed generated pages and media must be current: the production command runs
`optimize_assets.py --check`, `build_share_cards.py --check`, and
`render_site.py --check`, rejecting stale asset
hashes or generated output rather than modifying sources. The asset integrity
check loads image/font libraries only when generating new media, not when checking it.

```text
PRIVATE_CHECKOUT/                 Git pulls happen here; never served
  content/ data/ tools/ tests/    authoring catalogs and tooling
  dist/release/
    public/                      ONLY these files may be served
    release-manifest.json         private integrity inventory + route list
    90s-land.tar.gz               private reproducible transport archive
    90s-land.tar.gz.sha256

SITE_ROOT/                       separate from the checkout; never served as a whole
  releases/CONTENT_DIGEST/
    public/                      verified production files
    release-manifest.json        outside public/
    90s-land.tar.gz
    90s-land.tar.gz.sha256
  current -> releases/CONTENT_DIGEST/public
```

**Caddy's document root must already be `SITE_ROOT/current` for the publishing
commands below.** A pre-existing root that points at the checkout, `SITE_ROOT`,
`releases`, or the package directory does not satisfy this contract. Stop there
and request a separately authorized hosting correction. These scripts do not
read, edit, reload, restart, or otherwise configure Caddy; they cannot protect a
repository that a server is independently configured to expose.

## What crosses the public boundary

The packager starts with the catalog routes, 404 page, sitemap, robots file,
web manifest, and sharing images, then follows local runtime dependencies.
A positive path/type policy permits only route HTML, the four site stylesheets,
known browser modules, referenced image/font assets, required font licenses,
and two deliberately limited browser data files:

- `assets/runtime/week.json`: published event fields used for date navigation.
- `assets/runtime/surprise.json`: published stories, reviewed objects, defining events,
  years, collections and tours; only titles, teasers, dates, display labels,
  types, IDs, and destinations used by Surprise Me.

These are generated by `tools/render_site.py`, committed, and verified by its
`--check` mode. They contain no authoring review metadata. The raw `data/` and
`content/` catalogs are never copied. Git metadata, hidden files, environment
files, source fragments, tests, build tools, docs, reports, dependency folders,
source maps, and original hero artwork are excluded. Any dependency on a private
path, path traversal, or a symlink causes the build to fail. Symlinks are also
rejected inside the finished public directory.

Builds use temporary staging, validate before replacing a previous managed build,
remove obsolete files, and serialize concurrent operations. A failed build keeps
the previous verified package. The build output is staging, not a live directory:
use the publisher for an atomic live switch. Existing unrelated/non-verified
output directories are refused; move them aside explicitly before rebuilding.
Old Phase 5 schema-1 packages are historical evidence, not compatible deployment
inputs for this verifier. Retain them separately.

Schema 3 records the expanded discovery fields. The verifier also accepts
strict schema-2 inventories so an existing verified release can be replaced or
rolled back without weakening either schema’s data policy.

The manifest records sizes and SHA-256 hashes for every public file, route paths,
and a digest of the inventory. Text gzip sidecars and the transport archive use
fixed timestamps and permissions. Identical inputs and editorial date with the same Python/zlib
runtime produce identical files and archives; a different compression-library
version can change compressed bytes without changing the website. No network,
npm install, image generation, or font conversion enters packaging. The builder
refreshes Home and This Week using the current civil date in America/Denver and
records that date as `editorialAsOf` in the private manifest. Use
`--as-of YYYY-MM-DD` when reproducing a previous package. Only day-precision
events enter the weekly calendar; month/year entries remain in the wider archive.

Static hosting must rebuild and publish after the Denver date changes to keep
the default HTML current for crawlers and visitors without JavaScript. The browser
also recalculates the date while a page is open, but that does not refresh a stored
HTML file. After the operator confirms the deployment host and release store,
schedule the existing build/publish commands daily on that host. No remote scheduler
is installed by this checkout.

## Local checks before merging

Authoring changes still use the pinned development dependencies in
`requirements-dev.txt` and `pnpm-lock.yaml`. Regenerate with `pnpm author` if needed.

```sh
pnpm author:check
pnpm editorial:check
pnpm content:check
pnpm test:content
pnpm test:dates
python3 -B tools/audit_site.py
python3 -B tools/build_release.py
python3 -B tools/build_release.py --check
python3 -B tools/serve_release.py --port 4174
```

In a second terminal, test **the packaged release**, not the source tree:

```sh
python3 -B tools/check_release_http.py
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4174 pnpm test
```

The preview binds to localhost, verifies the package before serving it, negotiates
gzip, and sends the custom 404 page with status 404. It is not a production server
or proof of a particular VPS configuration. The HTTP audit checks every route,
private-path probes, identity/gzip bodies against the manifest, and compression
headers. Its default report is ignored `dist/deployment-http.json`.

## Deployment and rollback

Follow [DEPLOYMENT.md](../DEPLOYMENT.md) for the exact current Hermes procedure.
It captures the fetched `origin/main` SHA automatically, requires a clean source
snapshot, builds and verifies the public bundle, records the previous active
release, and uses the existing publisher for an atomic switch. No manual revision
numbers, release tags or server reconfiguration are required.

The first deployment requires checking the active production release for work
absent from GitHub. The included publisher is appropriate only when the existing
release layout satisfies its managed-release contract. Preserve a different
existing layout rather than migrating it during deployment.

Rollback uses the recorded previous complete release with the established
publisher, followed by the HTTP audit against that same package. Do not rebuild
old content from the latest checkout, rewrite Git history, delete prior releases,
or clear visitors' Passport/tour storage. There is no database migration.

## Existing Caddy serving requirements (verification only)

- Serve only `SITE_ROOT/current`, with `/section/` resolving to `index.html`.
- Preserve query strings/anchors, HTTPS, MIME types, and canonical 90s.land URLs.
- Return HTTP 404 for unknown/internal paths, with the site's 404 page if configured.
  No SPA fallback or directory listing is needed.
- Serve the provided gzip sidecars or apply equivalent dynamic gzip compression.
  Verify `Content-Encoding` and `Vary: Accept-Encoding`; sidecars alone do not enable it.
- Revalidate HTML, JSON, CSS, and JS. `Cache-Control: no-cache` is a safe initial
  policy because runtime filenames are not universally versioned.
- If a CSP is enforced, retain support for the existing small inline enhancement
  script. Do not weaken policy or strip that script during deployment.

Caddy's [root documentation](https://caddyserver.com/docs/caddyfile/directives/root)
and [file server documentation](https://caddyserver.com/docs/caddyfile/directives/file_server)
explain root selection, symlink behavior, compression, and error handling. A web
root is not a symlink sandbox, which is why the package rejects internal symlinks.
`.gitignore` controls Git tracking only; it is not HTTP access control. Neither a
robots rule nor an ignore file makes serving the checkout safe.
